Anti-patterns:
- Front-loaded multi-screen welcome tour, coach-mark carousel or video on first login (skipped, not remembered, no performance gain).
- Hiding required-field rules, units or photo instructions in hover-only tooltips (invisible on iPads; fails 'important information should always be on the page').
- Exposing internal enum names, codes or unexplained acronyms as statuses or labels ('RTD_BC', 'GISA_PEND', 'DEM').
- Calling the same object different names in different places (incident / ticket / field report; assessment / GISA / evaluation) or using different verbs for the same action.
- Validating on every keystroke in an empty or partially typed field, or showing errors only after submit with no inline validation.
- Clearing the form, losing uploaded photos, or resetting the map pin when validation fails; asking users to retype location data already captured in the incident report (violates WCAG 3.3.7).
- Color-only status badges or severity markers; dark uppercase tags that look like buttons; interactive tags.
- Blank tables, dashboards or map layers with no explanation of why they are empty or what to do next (dead ends).
- Locking the long GISA form into a strictly linear wizard that blocks skipping sections, saving mid-way or returning to earlier steps.
- Disabled 'Submit' or 'Route' buttons with no visible explanation of what is missing (USWDS: disabled states give poor feedback).

Anti-patterns:
- A numbered stepper for the 10-15 section GISA, where sections are conditional and completed out of order (USWDS says step indicators are only for linear, fixed-count flows).
- Validating on focus or while typing, or validating narratives on blur; disabling Submit until the form is valid; relying on HTML5 native validation bubbles (GOV.UK validation, USWDS 'don't disable in...
- Pre-selecting 'No' (or any option) on tri-state questions, or storing an unanswered question as 'No'; putting three options inline on a narrow screen.
- type='number' spinbuttons for measurements on iPad, or units shown only as placeholder text inside the field.
- Single-open accordions that auto-collapse sibling sections, no 'Expand all', and printing whatever happens to be expanded.
- Reproducing the paper form's multi-column grid on screen 'for parity' - parity should come from section numbering and content order, not layout.
- Silent autosave with no visible state, or removing explicit Save buttons because 'it autosaves' (NN/g: users expect Save/Apply and need feedback for every system process).
- Presenting the GISA on screen as an embedded PDF, or making PDF the only read-only view (NN/g: PDFs are unfit for on-screen reading; HTML first, PDF as download).
- Drag-and-drop-only dashboard customization, per-user free-form card layouts for rotating staff, and grab handles that look like menu icons.
- Reset/Clear-section buttons on long forms, session timeouts that discard drafts, and critical instructions hidden behind links that navigate away from the form.

Anti-patterns:
- One giant 'All incidents' table for every role with a dozen filters and no role-specific default queue (contradicts Jira's 'multiple simple queues' guidance and Linear's focus-order model).
- Sorting 'my work' by creation date or record ID instead of urgency, due date, and in-progress state.
- Flashing 'No records found' before the query resolves (NN/g: creates distrust and abandoned tasks).
- Empty states that are dead ends: no explanation of why the list is empty and no link to the next place to go; or empty-state copy that uses internal workflow status codes and jargon.
- Silently removing an item from a coordinator's or engineer's view after a handoff, with no trace that it was routed, returned, or approved.
- Delivering action-required events ('returned for revision', 'approval needed') only as dismissible toasts rather than persistent inbox rows.
- Modal confirmations and interstitials on routine, reversible queue actions (accept, route, assign) that break the triage rhythm.
- Mixing 'Browse all' and 'My Work' as tabs in one tab control (NN/g: mixing navigation tabs with in-page tabs disorients users); tab labels in ALL CAPS.
- Checkboxes and selection mode on read-only browse tables that offer no bulk action (Calcite: avoid selectionMode without associated interactions).
- Filter UIs with no applied-filter overview or 'Clear all', or single-value-only status filters (Baymard).
