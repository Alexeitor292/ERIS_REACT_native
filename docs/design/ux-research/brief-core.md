## Personas (from docs + code)

### Maintenance field reporter  -  codes: MAINTENANCE_FIELD_WORKER (canonical), MAINTENANCE (legacy)
Environment: Field / roadside / maintenance vehicle, often with poor connectivity; occasionally a district yard desk. Backend scopes them to their own reports only (backend/app/roles.py:58-60, 106-115; docs/assessment-routing-authority-model.md:125-129).
Devices: Phone (ERIS mobile app, primary), iPad (mobile app), Desktop web only for the 'New incident' intake panel on /incidents (web/src/utils/roleModel.ts:76-78; docs/CLIENTS_VERIFIED.md:20-22)

- Answer a coordinator's 'needs reporter information' request by editing only the allowed fields (district, county, route, post_mile, lat, lon, first_observed_at, first_occurred_at, description) via PATCH /incidents/{id} (backend/app/routes/...
- Sync the Road Inventory offline package (Me -> Road Inventory -> Sync Now) so the incident form can match segments offline (docs/field-workflow-qa.md:27-34; mobile/app/(tabs)/_layout.tsx:254-259) (frequency: Occasional, after admin publish...
- Work offline and let the queue replay when connectivity returns (docs/WORKFLOWS_VERIFIED.md:107-113) (frequency: Constant background concern, urgency: Medium - failed sync silently strands a report)
Must see:
- Only two tabs: Create Incident and Track Incidents (docs/WORKFLOWS_VERIFIED.md:99-105; docs/CLIENTS_VERIFIED.md:59-65)
- Confirmation that the report was created and media uploaded / queued
- Plain-language status of each own report and, when applicable, exactly which fields the coordinator wants corrected
- Road Inventory match confirmation (county, route, PM range, lanes, surface) and whether the offline dataset is current (amber vs version tag)

Should NOT be burdened with:
